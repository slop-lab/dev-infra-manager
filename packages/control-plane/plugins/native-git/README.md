# `@slop-lab/dim-plugin-control-plane-native-git`

The optional DIM Git authority owns imported Project repositories, proposal transport,
immutable review evidence, human approvals and protected-ref promotion. Ordinary
local and remote Git workspaces do not require this package.

Service composition belongs to `@slop-lab/dim-managed`. Its native Git service
entrypoint supplies the workflow compiler and serves the generation-bound
installed bundle. The native Git package provides the authority library and
operator review client. Configuration-only consumers use
`@slop-lab/dim-plugin-control-plane-native-git/config`; the `/service` entrypoint loads the authority
runtime and its persistent stores.

## Authority boundaries

A Project groups independent repositories, each with its own bare object database,
protected head, import receipt and reviewed policy. Host bootstrap imports each
repository through a bounded upload/finalization protocol. Project ownership is
shared, while registration, leases, reviews and promotion select a repository; service configuration
owns role credentials and Git execution settings. Repository registrations and
policy do not live in parallel static service registries.
Workspace writers receive short-lived credentials scoped to the Project,
workspace and proposal-ref namespace. CI readers receive credentials bound to
one exact execution attempt and candidate tuple. Neither obtains protected-ref
write authority or host controller credentials.

A proposal push records an immutable complete-tree review and job plan before
reporting success. Restart reconciliation finishes publication after an
interrupted push. Review evidence includes the expected protected head,
candidate commit/tree, policy revisions, changed paths, patch bytes and an exact
map of selected repository commits and trees. Jobs default to their own repository;
additional inputs must be allowed by the imported `ciRepositoryIds` policy.
Workers acquire only the selected trees, without guest Git credentials.

Human approval and revocation apply to the exact current review. Promotion
rechecks the policy, expected head, approvals and required CI evidence, then
updates the protected ref with compare-and-swap. Source or policy drift makes
previous evidence stale. Promotion changes one repository only; there is no
cross-repository transaction. Dependency head changes invalidate integration
evidence instead of silently refreshing its pinned inputs. The Git authority owns these decisions; CI workers
only report execution evidence.

## Workflow compilation

`configuredNativeGitBundleServer` requires a `WorkflowCompiler`. The compiler
chooses a repository-relative configuration path and produces jobs with names,
execution kinds, script paths and argument vectors. The authority validates
those paths and vectors, reads bounded regular blobs from the exact candidate
and records their object IDs and SHA-256 hashes. Returned job order is
canonicalized independently of the source language.

The managed service supplies `@slop-lab/dim-plugin-control-plane-ci-workflows`:

```yaml
jobs:
  source:
    script: scripts/check.sh
  integration:
    script: scripts/integration.sh
    runtime: qemu
```

The plugin owns syntax and supplies the Bash command. The authority library has
no YAML parser or dependency on that plugin. Other compositions can inject a
different language or configuration location. Trusted host policy owns images,
resources and credentials. Workers verify configuration/script identities
without interpreting the workflow language again.

All valid candidate jobs can be scheduled. Project quality policy independently
selects which jobs and execution kinds are required for promotion.

## Human review

Use a private generation-bound reviewer connection generated by the managed
control-plane setup, or the optional browser review application:

```bash
dim-native-git operator review resolve /private/reviewer.json project-a public PROPOSAL_REF
dim-native-git operator review inspect /private/reviewer.json project-a public REVIEW_ID
dim-native-git operator review approve /private/reviewer.json project-a public REVIEW_ID
dim-native-git operator review revoke /private/reviewer.json project-a public REVIEW_ID APPROVAL_ID
```

Promotion uses the separately scoped host-promoter connection:

```bash
dim-native-git operator review promote /private/promoter.json project-a public REVIEW_ID
```

The client reads a caller-owned mode-0600 connection file and sends its exact
generation with each operation. The service rejects stale generations and
credentials outside their role or Project scope.

## Development

Production source belongs to this package; tests and fixtures live in `tests/`.
Run `pnpm run check` or `pnpm run build` here. Installed-service tests exercise
real Git repositories, publication recovery, short-lived credential boundaries,
review decisions, terminal evidence and compare-and-swap promotion. Low-level
Git materialization tests use a minimal test smart-HTTP transport to cover
object identity, byte budgets and filesystem path safety independently.

## External webhooks

Private service configuration can allowlist signed external subscribers for
authoritative review creation and finalized promotion. Delivery/retry history is
durable and independent of CI. See [configuration and operator recovery](docs/external-webhooks.md).

## Standalone control-plane plugin

`@slop-lab/dim-plugin-control-plane-native-git` exports `controlPlanePlugin` for
`@slop-lab/dim-control-plane`. It requires one configured workflow compiler
plugin, such as `@slop-lab/dim-plugin-control-plane-ci-workflows`. This composition
does not install or import DIM core, managed workspaces, or a host controller.

Install with `dim installer install control-plane plugin PACKAGE...`, then select
the enabled packages in the runtime configuration. The native plugin configuration
is `{service, stateDirectory, readinessToken, activationToken, expectedGenerationId}`:
`service` is the complete validated native service configuration documented above.
Optional `listen: {host, port}` changes the standalone listener, including port 0
for disposable tests; omitting it preserves the installed service listener.
Stopping the runtime closes listeners, publication tasks and database ownership,
while preserving repositories and durable state. Existing Docker installer
preflight, activation and recovery commands retain their transaction boundary.
