# Merge policy

`@slop-lab/dim-control-plane-plugin-merge-policy` is an optional control-plane
plugin for promoting reviewed proposals to protected Git refs. Install it with
`git-repositories` and `code-review`; repository hosting alone never grants
workspaces protected-ref write access.

The plugin accepts a private configuration containing `hostPromoters`, an array
of `{hostId, username, password}` credentials. Passwords must contain at least 32
characters. An empty array grants no operator promotion authority. Credentials
must be distinct from other roles in the composed repository service. The host
identity must own the selected Project repository.

An operator authenticates to `GET /v1/host-promoter-identity` and submits
`POST /v1/projects/PROJECT/repositories/REPOSITORY/reviews/REVIEW/promotions`
with Basic authentication, the current `X-Dim-Generation-Id`, and JSON
`{"schemaVersion":1}`. Human-review credentials cannot promote; promoter
credentials cannot approve reviews.

Use the private `promoter.json` generated by control-plane connect:

```bash
dim-merge-policy promote /absolute/path/promoter.json PROJECT REPOSITORY REVIEW_ID
```

The client checks file ownership, mode 0600, host identity and deployment
generation before submitting a promotion.

Promotion checks the exact current proposal, protected head, imported policy
and human approvals. The complete canonical policy digest binds the review, so
changing quality policy requires a fresh review. Optional quality providers
contribute `dim.merge-policy.quality-guard` extensions through `/extensions`.
Every review attachment and every trusted policy namespace other than
`code-review` and `merge-policy` requires its matching guard. A required CI
policy therefore fails closed if the CI plugin or its preparation is missing.
A repository using only human review requires no CI installation.

Merge evidence and decisions live in this plugin's private extension state
SQLite database. The repository engine owns the serialized, recoverable Git
compare-and-swap journal. On restart the merge plugin reconciles only operations
already accepted by that journal; it never retries an unsent authorization
without fresh approval and policy checks. Concurrent promotion requests produce
one transition and an idempotent already-current receipt.

The plugin contributes a structural `dim.webhooks.event-source` named
`merge-policy`, emitting durable `dev.dim.git.ref.promoted` metadata for completed
promotions. The optional webhooks plugin owns transport, subscribers, credentials
and retry state. Installing merge policy does not install or contact webhook
receivers.

The package's `/config` export parses configuration without loading the SQLite
or Git service implementation. `/extensions` exposes the quality-check port;
the repository serialization gate is already held while a guard executes.
