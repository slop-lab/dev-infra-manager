# Cloudflare DNS + Caddy HTTPS ingress

This directory shows the files generated by:

```bash
dim external-url add-provider cloudflare cloudflare-main \
  --zone example.com \
  --record-type A \
  --target 203.0.113.10 \
  --credential-env CF_API_TOKEN

dim external-url add-ingress public-https \
  --driver caddy \
  --description "Public HTTPS development URL" \
  --scheme https \
  --domain dev.example.com \
  --listen-host 127.0.0.1 \
  --listen-port 9080 \
  --provider cloudflare-main

CF_API_TOKEN=... dim external-url setup-ingress public-https \
  --output .dim/external-url
```

`setup-ingress` idempotently reconciles `*.dev.example.com` in Cloudflare and
writes a Caddy deployment. Copy `.env.example` to `.env`, supply the same
zone-scoped token, and start it:

```bash
cd .dim/external-url/public-https
cp .env.example .env
docker compose up --detach --build
dim external-url verify-ingress public-https
```

The token requires `Zone.Zone:Read` and `Zone.DNS:Edit`, restricted to the
configured zone. Caddy uses it only for ACME DNS-01 issuance and renewal.
